홈페이지를 새로 만들었는데 검색에 안 나옵니다

새 홈페이지가 구글·네이버에 안 잡히는 이유는 대부분 정해져 있습니다. 색인을 막는 설정부터 순서대로 확인하는 방법, 제출 후 걸리는 기간, 직접 볼지 맡길지 판단 기준까지 실무 경험으로 정리했습니다.

작성자 오경록 · 아비컴퍼니 대표 발행일 2026-08-25 수정일 2026-09-27
핵심 요약
  • 새 사이트가 안 나오는 이유는 순위 문제가 아니라 대개 색인 문제입니다.
  • noindex 태그와 robots.txt 차단이 가장 흔한 원인이고, 둘 다 한 줄로 전체를 막습니다.
  • 사이트맵에 리디렉션되는 주소를 실으면 구글이 그 페이지를 색인에서 뺍니다.
  • 제출은 서치콘솔·서치어드바이저에서 하고, 반영에는 시간이 걸립니다.
  • 확인 순서는 site: 검색 → URL 검사 → 응답 헤더 → robots.txt → 사이트맵 5단계이고, 여기까지 20~30분이면 원인이 대개 드러납니다.
  • 색인 자체는 구글이 보통 1~7일, 네이버가 3~14일이며 개설 3개월 미만 신규 도메인은 2~4주가 더 붙는 경우가 많습니다.

홈페이지를 새로 열고 2주쯤 지나면 거의 같은 연락을 받습니다.

"회사 이름으로 검색해도 안 나오는데요."

실제 운영해 보면 이때 순위를 손보는 것은 거의 의미가 없습니다.

아직 순위 경쟁에 들어가지도 못한 상태, 즉 검색엔진이 페이지를 목록에 넣지 않은 상태이기 때문입니다.

그래서 확인 순서가 중요합니다. 위에서부터 하나씩 짚어야 시간을 낭비하지 않습니다.

먼저 색인이 됐는지 어떻게 확인하나요?

검색창에 `site:` 를 붙여 도메인을 넣어 보는 것이 가장 빠릅니다.

결과가 하나도 안 나오면 순위가 낮은 것이 아니라 아예 등록되지 않은 것입니다.

정확히 보려면 구글 서치콘솔의 URL 검사 기능을 씁니다. 해당 주소가 색인됐는지, 안 됐다면 이유가 무엇인지 알려 줍니다.

여기서 나오는 사유 문구가 다음에 무엇을 고쳐야 하는지 그대로 알려 줍니다.

서치콘솔에 뜨는 사유실제 원인조치
'noindex' 태그에 의해 제외됨페이지가 색인 거부를 스스로 선언meta robots 와 X-Robots-Tag 헤더 확인
robots.txt에 의해 차단됨크롤러 접근 자체를 막음Disallow 규칙 수정
리디렉션이 포함된 페이지제출한 주소가 다른 주소로 넘어감사이트맵·canonical 을 최종 주소로
크롤링됨 - 현재 색인 생성 안 됨내용이 얕거나 중복으로 판단본문 보강, 중복 페이지 정리
발견됨 - 현재 색인 생성 안 됨대기 중이거나 우선순위 낮음내부링크 보강 후 기다림

표의 다섯 가지 중 위 세 가지는 설정 문제라 고치면 며칠 안에 바뀝니다. 아래 두 가지는 내용과 시간 문제라서 즉시 해결되지 않습니다.

이 구분을 먼저 해야 어디에 시간을 쓸지 정할 수 있습니다.

가장 흔한 원인은 무엇인가요?

제작 중에 걸어 둔 색인 차단을 그대로 두고 오픈한 경우입니다.

실제로 문의를 받아 점검해 보면 설정 문제로 끝나는 경우가 상당수이고, 그 안에서도 noindex 잔존과 robots.txt 전체 차단 두 가지가 가장 자주 나옵니다.

작업 중인 사이트가 검색에 노출되면 곤란하니 막아 두는 것은 정상입니다. 문제는 여는 날 푸는 것을 잊는 것입니다.

특히 워드프레스는 설정 안에 체크박스 하나로 전체 색인을 막는 기능이 있어서, 이것 하나로 몇 달을 날리는 경우를 봤습니다.

직접 만든 사이트라면 두 군데를 봐야 합니다.

  • HTML 안의 meta robots 태그에 noindex 가 들어 있는지
  • 서버가 X-Robots-Tag 헤더로 noindex 를 내보내는지
  • robots.txt 에 Disallow: / 가 남아 있는지
  • 스테이징 도메인용 설정이 운영 도메인에 그대로 배포됐는지
놓치기 쉬운 지점

meta 태그에는 index 라고 적혀 있어도 서버가 헤더로 noindex 를 보내면 헤더가 이깁니다. 브라우저에서 소스만 봐서는 보이지 않기 때문에, 응답 헤더까지 확인해야 원인을 찾을 수 있습니다.

원인은 어떤 순서로 좁혀 나가나요?

아래 5단계를 위에서부터 그대로 밟으면 됩니다. 도구 사용법을 익히는 시간까지 합해도 보통 20~30분이면 끝나고, 앞 단계가 막혀 있으면 뒤 단계는 볼 필요가 없습니다.

순서를 건너뛰고 사이트맵부터 손대는 경우가 많은데, 차단이 걸린 상태에서는 사이트맵을 몇 번 다시 내도 결과가 바뀌지 않습니다.

원인을 좁히는 5단계
1
site: 검색 (1분)결과 0건이면 색인 문제, 결과가 있으면 순위 문제로 갈라집니다.
2
URL 검사 (3분)서치콘솔에서 대표 주소 1개를 넣어 제외 사유 문구를 확인합니다.
3
응답 헤더 (5분)X-Robots-Tag 에 noindex 가 실려 있는지 봅니다. 소스만 봐서는 안 보입니다.
4
robots.txt (2분)도메인 뒤에 /robots.txt 를 붙여 열고 Disallow: / 가 있는지 봅니다.
5
사이트맵 (10분)실린 주소를 10개쯤 눌러 보고 리디렉션·404 가 섞였는지 봅니다.

▲ 1~4 단계에서 원인이 나오면 5단계는 고친 뒤에 확인하면 됩니다

사이트맵만 내면 되는 것 아닌가요?

사이트맵은 목록일 뿐이고, 그 목록이 정확해야 효과가 있습니다.

실제 운영해 보면 사이트맵 자체가 문제를 만드는 경우가 적지 않습니다.

대표적인 것이 최종 주소가 아닌 주소를 싣는 경우입니다.

예를 들어 서버가 `/page.html` 을 `/page` 로 넘기는데 사이트맵에는 `.html` 주소가 들어 있으면, 구글은 제출받은 주소마다 리디렉션을 만나고 그 페이지를 색인에서 뺍니다.

사이트맵에 실으면 안 되는 주소
리디렉션되는 주소301·308 로 넘어가는 주소는 최종 주소로 바꿔 싣습니다.
noindex 페이지색인을 막아 둔 페이지를 사이트맵에 넣으면 신호가 어긋납니다.
검색·페이지 목록검색 결과나 2페이지 이후는 색인 대상이 아닙니다.
canonical 이 다른 페이지대표 주소가 따로 있는 페이지는 그 주소만 싣습니다.

▲ 제출한 주소와 실제로 열리는 주소가 같아야 합니다

점검할 때는 사이트맵에 실린 주소 중 10개 정도를 직접 눌러 봅니다. 주소창의 주소가 바뀌거나 404 가 나오는 것이 하나라도 있으면 전체를 다시 봐야 합니다.

페이지가 20개 안팎인 사이트라면 사이트맵을 손으로 관리해도 되지만, 30~50개를 넘어가면 자동 생성으로 바꾸는 편이 안전합니다. 손으로 유지하면 페이지를 지웠을 때 주소가 남는 일이 반복됩니다.

구글과 네이버, 어디부터 등록해야 하나요?

둘 다 등록하는 것이 기본이고, 순서만 정하면 됩니다. 지역·서비스 업종이라면 반영 속도를 직접 통제할 수 있는 네이버 서치어드바이저부터, 정보성 검색 유입이 큰 분야라면 구글 서치콘솔부터 잡는 편이 체감이 빠릅니다.

설정 자체는 서로 공유됩니다. robots.txt, 사이트맵, meta 태그는 한 번 제대로 맞추면 양쪽에 함께 적용되므로, 어디를 먼저 등록하느냐가 작업량을 늘리지는 않습니다.

비교 축구글 서치콘솔네이버 서치어드바이저
소유권 확인 방법HTML 파일 업로드·메타 태그·DNSHTML 파일 업로드·메타 태그
개별 주소 요청URL 검사에서 건별 색인 요청웹페이지 수집 요청(계정별 일일 한도 있음)
원인 진단 화면색인 생성 범위·URL 검사 사유 문구웹마스터 도구 진단·수집 현황
평균 색인 기간보통 1~7일보통 3~14일
먼저 하기 좋은 업종정보성 검색·전국 단위·해외 노출지역 업종·서비스업·상호 검색 비중이 큰 곳

정리하면 발행 직후 빠른 반영이 필요하면 네이버 수집 요청을, 장기 누적 노출이 목표면 구글 사이트맵 관리를 중심에 둡니다.

제출은 어디서 하고 얼마나 걸리나요?

구글은 서치콘솔, 네이버는 서치어드바이저에 사이트를 등록하고 사이트맵을 제출합니다.

등록 자체는 십 분이면 끝나지만, 실제로 목록에 오르는 데는 시간이 걸립니다.

운영 이력이 있는 도메인이면 구글은 보통 1~7일, 네이버는 3~14일 안에 잡히는 경우가 많습니다. 개설 3개월 미만의 신규 도메인은 여기에 2~4주가 더 붙는 것이 일반적입니다.

새 도메인은 특히 그렇습니다. 며칠에서 몇 주까지도 걸리며, 이 구간에서 초조해져 설정을 이것저것 바꾸다 오히려 꼬이는 경우가 많습니다.

제출한 뒤에는 서치콘솔의 색인 현황만 주기적으로 보면서 기다리는 편이 낫습니다. 확인 주기는 3일에 한 번 정도가 적당하고, 3주가 지나도 한 건도 잡히지 않으면 기다리는 대신 설정을 다시 봅니다.

실무 팁

새 사이트일수록 내부링크가 중요합니다. 메인에서 모든 주요 페이지로 한 번에 닿을 수 있으면 크롤러가 훨씬 빨리 전체를 훑습니다. 어디서도 링크되지 않은 페이지는 사이트맵에만 있어도 뒤로 밀립니다.

직접 볼지 맡길지 어떻게 판단하나요?

관리자 화면에서 체크박스를 푸는 수준이면 직접 하는 것이 빠르고, 서버 헤더나 배포 설정을 건드려야 하면 만든 쪽에 맡기는 편이 낫습니다. 기준은 난이도가 아니라 '고친 뒤 되돌릴 수 있는지'입니다.

제작한 업체가 있다면 먼저 연락하는 것이 맞습니다. 오픈 직후 색인 차단이 남아 있는 것은 제작 과정에서 생긴 문제이므로, 유상 작업이 아니라 하자 처리로 봐야 하는 경우가 많습니다.

비교 축직접 점검제작업체·대행사에 의뢰
맞는 상황워드프레스 체크박스·robots.txt 한 줄 수정서버 헤더·배포 설정·대량 리디렉션 정리
필요한 것서치콘솔 계정과 관리자 권한소스·서버 접근 권한을 가진 담당자
걸리는 시간점검 20~30분, 수정 10분 내외협의 포함 2~5영업일
비용없음제작사 하자 처리면 무상, 별건 점검·수정 의뢰는 보통 20~80만 원 선에서 견적이 나옵니다
위험헤더 문제를 놓쳐 원인을 못 찾을 수 있음설명 없이 설정만 바뀌면 다음에 또 모름

어느 쪽이든 고친 다음에는 서치콘솔 URL 검사에서 사유 문구가 사라졌는지 확인하고 기록을 남깁니다. 무엇을 왜 바꿨는지가 남아 있으면 다음 개편 때 같은 문제를 반복하지 않습니다.

그래도 안 나오면 무엇을 봐야 하나요?

색인은 됐는데 검색 결과에서 안 보이는 경우라면, 그때부터가 순위 이야기입니다.

회사 이름으로도 안 나온다면 상호가 본문에 제대로 적혀 있는지, 사업자 정보와 연락처가 일관되게 들어가 있는지부터 봅니다.

지역 업종이라면 지도 등록 정보와 홈페이지의 상호·주소·전화번호가 같은 값인지도 확인해야 합니다.

값이 서로 다르면 검색엔진이 같은 업체로 묶지 못합니다. 띄어쓰기와 지번·도로명 표기까지 한 글자 단위로 맞추는 편이 안전합니다.

여기까지 정리하고 나서 콘텐츠를 쌓아야 시간이 헛되지 않습니다.

콘텐츠 단계로 넘어가면 결과가 나타나는 속도도 달라집니다. 설정 수정은 며칠 안에 반영되지만, 내용으로 순위를 만드는 일은 보통 3~6개월 단위로 봅니다.

오픈 전에 확인할 체크리스트는 무엇인가요?

오픈 당일에 아래 8개만 확인하면 색인 사고는 대부분 막을 수 있습니다. 항목당 1~3분이면 되고, 순서대로 위에서 아래로 봅니다.

  • meta robots 에 noindex 가 남아 있지 않은지 — 주요 페이지 3~5개를 표본으로 확인합니다.
  • 응답 헤더의 X-Robots-Tag 에 noindex 가 실려 있지 않은지 — 소스 보기로는 안 보입니다.
  • robots.txt 에 Disallow: / 가 없고 Sitemap 경로가 한 줄 들어 있는지 확인합니다.
  • 사이트맵에 실린 주소가 실제로 열리는 최종 주소와 같은지 10개쯤 눌러 봅니다.
  • canonical 이 각 페이지의 대표 주소를 절대경로로 1개만 가리키는지 봅니다.
  • www 유무와 http·https 중 어느 주소가 대표인지 정하고, 나머지는 그 주소로 넘어가는지 봅니다.
  • 스테이징 도메인용 설정이 운영 도메인에 그대로 배포되지 않았는지 확인합니다.
  • 서치콘솔·서치어드바이저 소유권 확인과 사이트맵 제출을 마쳤는지 봅니다.
정리

새 사이트가 검색에 안 나올 때는 순위를 올리는 작업이 아니라 막힌 곳을 찾는 작업이 먼저입니다. 색인을 여는 것은 좋은 결과를 약속하는 장치가 아니라, 공들여 만든 페이지가 평가받을 기회를 만드는 최소 조건입니다.

자주 묻는 질문

새 홈페이지가 검색에 안 나옵니다. 얼마나 기다려 봐야 하나요?

운영 이력이 있는 도메인이면 구글은 보통 1~7일, 네이버는 3~14일 안에 색인되는 경우가 많습니다. 개설 3개월 미만의 신규 도메인은 여기에 2~4주가 더 붙는 것이 일반적입니다. 다만 무작정 기다리기보다 제출 직후 site: 검색과 서치콘솔 URL 검사로 상태를 한 번 확인하는 편이 낫습니다. 3주가 지나도 한 건도 잡히지 않으면 기다리는 단계가 아니라 설정을 점검하는 단계입니다.

색인이 안 된 것과 순위가 낮은 것은 어떻게 구분하나요?

검색창에 site: 뒤에 도메인이나 특정 글 주소를 넣어 조회해 보면 바로 구분됩니다. 결과가 하나도 나오지 않으면 검색 목록에 등록조차 되지 않은 색인 문제이고, 결과가 나오는데 일반 검색에서 안 보이면 순위 문제입니다. 두 상황은 원인도 대응도 완전히 다릅니다. 색인 문제는 설정을 고쳐 며칠 안에 바뀌지만, 순위는 내용과 링크를 쌓아 보통 3~6개월 단위로 움직입니다.

meta 태그에 index 라고 적혀 있는데도 색인이 안 되는 이유가 있나요?

서버가 응답 헤더로 X-Robots-Tag: noindex 를 함께 보내는 경우가 있습니다. 이때는 HTML 안의 meta 태그보다 헤더 쪽 지시가 우선 적용되어 색인이 막힙니다. 브라우저에서 소스 보기만으로는 드러나지 않기 때문에 개발자도구의 네트워크 탭이나 서치콘솔 URL 검사로 응답 헤더까지 확인해야 합니다. 스테이징 환경용 설정이 운영 서버에 그대로 배포됐을 때 자주 나오는 형태입니다.

사이트맵은 몇 번이나 다시 제출해야 하나요?

사이트맵 주소는 한 번만 등록하면 되고, 이후에는 내용이 갱신되면 검색엔진이 다시 읽어 갑니다. 반복 제출보다 사이트맵에 실린 주소가 정확한지가 훨씬 중요합니다. 리디렉션되는 주소, 404 주소, noindex 페이지가 섞여 있으면 목록 전체의 신뢰도가 떨어집니다. 페이지를 새로 만들거나 크게 보강했다면 lastmod 값을 갱신하고 개별 주소로 색인·수집 요청을 한 번 넣는 정도가 적당합니다.

회사 이름으로 검색해도 안 나오는데 광고를 돌리면 해결되나요?

광고는 검색 결과의 광고 영역에 노출되는 것이고, 색인이 막힌 상태를 풀어 주지는 않습니다. 광고를 멈추면 다시 보이지 않게 되므로 원인 해결과는 별개입니다. 먼저 noindex·robots.txt·사이트맵을 점검해 색인을 열고, 상호와 사업자 정보가 본문에 일관되게 들어가 있는지 확인하는 순서가 맞습니다. 색인이 정리된 뒤에 광고를 쓰면 같은 예산으로 얻는 결과가 달라집니다.

제작업체에 다시 요청하면 추가 비용이 드나요?

오픈 직후 색인 차단이 남아 있는 경우라면 제작 과정에서 생긴 문제이므로 하자 처리로 무상 대응하는 경우가 많습니다. 계약서의 하자보수 기간과 범위 조항을 먼저 확인하고 연락하면 이야기가 빠릅니다. 반면 사이트맵 구조 변경이나 대량 리디렉션 정리처럼 새 작업에 가까운 건은 별건으로 보통 20~80만 원 선의 견적이 나옵니다. 어느 쪽이든 무엇을 왜 바꿨는지 기록으로 받아 두면 다음 개편 때 같은 문제를 반복하지 않습니다.

정리하면 순서는 색인 확인 → 차단 해제 → 사이트맵 정리 → 제출 → 대기이고, 그다음이 내용과 순위입니다. 이 순서를 지키면 새 사이트가 검색에서 조용한 기간을 크게 줄일 수 있습니다.
